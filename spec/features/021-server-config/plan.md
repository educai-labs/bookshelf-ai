# 021 · Server Config — Plan

## Enfoque

Ampliar la configuración existente de FastAPI en `apps/api/app/core/config.py` usando `BaseSettings` de Pydantic v2, con enums, restricciones positivas, URLs tipadas y defaults explícitos. La instancia singleton seguirá siendo la fuente de verdad y `get_settings` seguirá siendo utilizable como dependencia de FastAPI; los tests crearán instancias con overrides sin modificar el `.env` real.

Integrar esa configuración en el arranque de la API, CORS y logging estructurado. La validación de credenciales obligatorias se hará fail-fast únicamente en producción, mientras que desarrollo y tests conservarán defaults seguros para poder ejecutar health checks. La redacción se colocará en el pipeline de logging antes del renderer para cubrir tanto consola como JSON.

## Implementación

1. **Definir el modelo completo de configuración — `apps/api/app/core/config.py`.** Sustituir los campos parciales actuales por `Settings(BaseSettings)` con las secciones de entorno, Supabase, Gemini, frontend/CORS, servicios externos, logging y seguridad. Añadir enums para `APP_ENV`, `LOG_LEVEL` y `LOG_FORMAT`; usar restricciones Pydantic para puertos, timeouts y límites por minuto; tipar las URLs como `HttpUrl` (opcionales solo cuando el entorno local permita ausencia); y declarar defaults explícitos para todos los flags booleanos y valores opcionales.
2. **Fijar la configuración de embeddings — `apps/api/app/core/config.py`.** Declarar `EMBEDDING_MODEL = "text-embedding-004"` y `EMBEDDING_DIMENSIONS = 768` como constantes de clase no configurables. No exponerlas como campos de `Settings`; documentar que, con `extra="ignore"`, los intentos de establecer `EMBEDDING_MODEL` o `EMBEDDING_DIMENSIONS` desde el entorno se ignoran, evitando cambios accidentales que exigirían re-vectorización.
3. **Validar por entorno y exponer la dependencia — `apps/api/app/core/config.py`.** Configurar `SettingsConfigDict` para `.env`, case-insensitive y variables extra ignoradas, mantener `get_settings()` cacheado y `settings` como singleton. Añadir un validador de producción que recopile todas las credenciales críticas ausentes y lance un error de validación que nombre cada variable; incluir como mínimo `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_JWT_SECRET`, `SUPABASE_JWKS_URL` y `GEMINI_API_KEY`. Mantener la construcción directa `Settings(_env_file=None, **overrides)` disponible para fixtures y tests.
4. **Aplicar la configuración al arranque y CORS — `apps/api/app/main.py`.** Usar `settings.app_version`, `settings.cors_origins` y `settings.log_level`/`settings.log_format` en lugar de valores hardcodeados. Ejecutar la validación de arranque antes de inicializar clientes externos y configurar `CORSMiddleware` con los orígenes parseados; rechazar `*` y cualquier origen no oficial cuando `APP_ENV=production`, sin permitir credenciales con wildcard.
5. **Implementar redacción previa al renderizado — `apps/api/app/core/logging.py`.** Añadir un processor/filtro de structlog que inspeccione eventos y valores anidados, redacte por nombre y patrón API keys, JWTs, cookies, `service_role`, y elimine o reemplace completamente el contenido de notas y prompts privados. Insertarlo antes de `JSONRenderer`/`ConsoleRenderer`, conservar el nivel y formato configurables y evitar que la redacción dependa de que el llamador use un nombre de campo concreto.
6. **Completar la documentación de entorno — `.env.example`.** Reorganizar el archivo por las siete secciones de la feature y documentar cada variable con comentario breve y ejemplo no secreto, incluidos `APP_ENV` para dev/test/production, URLs, CORS, timeouts, límites, flags, Sentry y claves opcionales. Mantener las variables de autenticación existentes que sigan siendo consumidas por el proyecto y dejar explícito que `SUPABASE_SERVICE_ROLE_KEY` solo existe en backend/MCP.
7. **Añadir tests del modelo y fail-fast — `apps/api/tests/test_config.py`.** Cubrir carga válida con overrides, coerción de valores esperados, defaults, enums, URLs, límites positivos, errores `ValidationError` con campo y razón, constantes de embeddings y ausencia de efectos sobre `.env`. Probar que producción reporta los nombres de todas las credenciales faltantes y que una configuración válida de producción arranca sin error.
8. **Añadir tests de logging — `apps/api/tests/test_logging.py`.** Configurar un logger capturado en formato consola y JSON, emitir valores representativos de API key, JWT, cookie, service role, nota y prompt, y verificar que ninguno aparece sin redactar en la salida. Comprobar también que eventos normales conservan sus campos útiles.
9. **Añadir regresión de aislamiento frontend — `apps/api/tests/test_config.py` o `apps/api/tests/test_security_boundaries.py`.** Leer recursivamente los archivos de `apps/web` desde el test y afirmar que no existe ninguna referencia a `SERVICE_ROLE_KEY`, tal como exige el límite duro de la constitución; no importar módulos del frontend ni introducir la clave en variables `NEXT_PUBLIC_*`.
10. **Validar la integración completa.** Ejecutar `cd apps/api && pytest -v`, `cd apps/api && ruff check . && black --check .`, y `cd apps/api && docker build -t bookshelf-api .`; revisar además que `grep -r "SERVICE_ROLE_KEY" apps/web` no devuelva referencias y que no se agreguen secretos ni archivos `.env*` al repositorio.

## Decisiones

- **Singleton cacheado más instancias con overrides** — `settings` y `get_settings()` mantienen compatibilidad con el backend existente y evitan recargar el entorno en runtime; las instancias directas con `_env_file=None` permiten tests aislados. No se usará un diccionario global mutable ni configuración dinámica desde la UI.
- **Embeddings como `ClassVar`/constantes, no como campos de settings** — hace imposible cambiar el modelo o dimensiones mediante variables de entorno y protege la compatibilidad con `vector(768)`; no se acepta hacerlos configurables con un default, porque permitiría desalinear vectores existentes.
- **Fail-fast condicionado a producción** — se exige el conjunto explícito de credenciales críticas al construir la configuración de producción y se reportan todas las ausencias en un solo error; desarrollo y tests no requieren secretos reales para health checks. No se pospone la detección hasta la primera llamada a Gemini o Supabase.
- **CORS como lista parseada desde entorno** — se acepta una lista separada por comas normalizada y validada; producción solo permite los orígenes oficiales y nunca `*`. No se mantendrá la lista fija de `main.py`, porque impediría desplegar distintos entornos de forma segura.
- **Redacción en processor de logging antes del renderer** — cubre structlog y ambos formatos de salida en un punto único, con defensa por nombres y patrones; no se confiará en que cada endpoint recuerde ocultar secretos ni se imprimirá el valor original en mensajes de error.
- **Sin dependencia nueva** — se reutilizan Pydantic-Settings, Pydantic y structlog ya declarados en `apps/api/pyproject.toml`; no se añadirá una librería de configuración, logging o rate limiting porque esta feature solo define settings y flags, no implementa observabilidad avanzada ni enforcement de límites.

## Riesgos

- **La validación global rompe imports de tests o health checks sin `.env`** — limitar el fail-fast al entorno `production`, usar overrides explícitos en fixtures y construir tests con `_env_file=None`; verificar también el arranque local con defaults.
- **URLs vacías no cumplen `HttpUrl` o no permiten desarrollo** — modelar como opcionales únicamente los valores no obligatorios fuera de producción y validar su presencia mediante el chequeo de credenciales críticas; probar URL válida, ausente permitida e inválida por separado.
- **CORS acepta un origen inseguro o wildcard en producción** — normalizar y validar la lista durante la creación de settings, rechazar `*` y comparar contra la allowlist oficial; cubrirlo con tests de producción y de desarrollo.
- **El redactor deja escapar secretos anidados o divididos en mensajes** — recorrer mappings, listas y valores serializables, aplicar reglas por nombre y patrones de JWT/API key, y probar campos anidados junto con eventos estructurados en consola y JSON.
- **La redacción elimina información útil o altera tipos inesperadamente** — redactar solo campos sensibles y contenidos privados completos, conservar metadatos no sensibles y ejecutar la suite existente de logging/health junto a los nuevos tests.
- **Una referencia accidental a `SERVICE_ROLE_KEY` llega al bundle o al código web** — mantener la variable exclusivamente en `apps/api`/MCP, añadir el test de regresión solicitado y revisar el resultado de `grep` antes de cerrar la feature.
- **Nombres de variables incompatibles con módulos existentes** — mantener aliases/case-insensitive mapping para los nombres `UPPER_SNAKE_CASE` de la spec y actualizar los consumidores para usar atributos de `settings`; ejecutar pytest, Ruff, Black y build de imagen al finalizar.
