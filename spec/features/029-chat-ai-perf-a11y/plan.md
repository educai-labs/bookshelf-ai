# 029 · Chat AI Perf & A11y — Plan

## Enfoque

Se reforzará el chat existente en el frontend Next.js sin cambiar el endpoint ni el protocolo SSE y sin añadir dependencias. El control de ciclo de vida se centralizará entre `ChatPage` y `streamChat` mediante `AbortSignal`, mientras que la persistencia y el renderizado se desacoplarán del ritmo de cada token: el historial se escribirá con debounce y el HTML se memoizará por contenido. Se conservarán los componentes shadcn/i18n actuales, añadiendo los atributos y acciones accesibles, la sanitización segura y pruebas Vitest/RTL para cada criterio antes de ejecutar test, lint y build.

## Decisiones

- **AbortSignal opcional en `streamChat`** — Se mantiene `fetch` + `ReadableStream` porque el endpoint es POST y requiere autenticación; añadir una señal opcional permite cancelar sin cambiar el protocolo SSE ni romper consumidores existentes. `EventSource` y cambios backend quedan descartados.
- **Debounce más flush de finalización** — El historial sigue en `sessionStorage`, pero no se serializa por token; un debounce de al menos 300 ms reduce trabajo durante streams y el flush al terminar/detener evita perder el estado final. No se introduce almacenamiento persistente ni una cola/dependencia nueva.
- **Ids generados en el cliente con compatibilidad de hidratación** — Los ids estables eliminan las keys por índice; los historiales previos se normalizan al cargarse y los mensajes nuevos reciben ids, sin cambiar el formato funcional `{ role, content }` que se guarda.
- **Memoización por contenido en el componente de mensaje** — `useMemo` local evita recalcular `marked` + DOMPurify para mensajes no modificados durante renders de otros mensajes; no se añade caché global, virtualización ni dependencia adicional.
- **Cancelación como resultado controlado** — Abort al desmontar, navegar o pulsar Detener no se presenta como error y conserva el contenido parcial; los fallos HTTP/SSE reales siguen usando el flujo i18n existente y el retry reutiliza el último mensaje del usuario.
- **Scroll basado en `prefers-reduced-motion`** — Se consulta la media query y se usa comportamiento instantáneo cuando corresponde, manteniendo el auto-scroll normal para el resto; no se fuerza una animación CSS ni una librería de accesibilidad.
- **Hook de DOMPurify para enlaces** — `afterSanitizeAttributes` centraliza la garantía de `rel` después del saneado y solo afecta a `target="_blank"`; no se permite confiar en el Markdown de entrada ni en un postprocesado inseguro del HTML.

## Riesgos

- **Timers y flush generan escrituras extra o pruebas flakey** — Usar un único timer cancelable, limpiar refs en cleanup y probar con fake timers/spy; el criterio permite como máximo una escritura por ventana o la de finalización.
- **Abort produce actualizaciones después del unmount o borra el parcial** — Guardar el controller y una bandera de componente activo, comprobar el motivo de cancelación en catch/finally y actualizar el mensaje parcial mediante functional state updates; probar unmount y Detener por separado.
- **Ids rompen historiales o expectativas existentes** — Normalizar ids solo en memoria y conservar la forma serializada histórica, aceptar entradas antiguas y actualizar únicamente tests que dependan de la identidad interna.
- **Memoización oculta cambios de traducción o mocks** — La memoización dependerá exclusivamente del contenido, mientras que el texto/rol se mantiene fuera del HTML; el test hará spy del helper y verificará cambios de contenido.
- **`prefers-reduced-motion` no está disponible en SSR/jsdom** — Proteger el acceso a `matchMedia`, definir fallback no animado y mockear listeners/resultado en tests sin leer APIs del navegador durante render SSR.
- **Cambios de Alert/Input alteran navegación por teclado o i18n** — Reutilizar `AlertTitle`/`Button` de shadcn, mantener orden de foco y claves paralelas `es`/`en`; ejecutar la suite completa y lint/build para detectar contratos rotos.
- **Hook de DOMPurify modifica configuración global o no aplica al atributo** — Registrar el hook de forma controlada/idempotente o usar la opción equivalente soportada por la versión instalada, limitar la mutación a enlaces `_blank` y probar salida real con `sanitizeHtml`.
